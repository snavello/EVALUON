# Avisos para T-072

## De la verificación de T-071 (2026-10-03)

- El manejador `read_document` se registra en `evaluon.tenders.jobs.HANDLERS` por su ruta (`"evaluon.tenders.services.documents.run_read_document"`), para no importar `jobs` en círculo. Recibe el `Job` ya `running`; si vuelve sin error el pedido queda `done`, y cualquier excepción lo deja `failed` con `Tipo: mensaje` (o `timeout: …` si es una falla del cliente de IA). No marques el estado del pedido desde el manejador.
- El manejador puede cortarse en cualquier punto (`docker compose stop` deja el pedido `failed` "interrumpido"; un `SIGKILL` lo deja `running` hasta el próximo arranque, que lo cierra). Lo que haga en la base conviene hacerlo en una transacción, para que una lectura cortada no quede a medias.
- `procesar_pedidos` supone una sola instancia: al arrancar pasa a `failed` **todos** los pedidos `running`. Correr un segundo `procesar_pedidos` (por ejemplo, `docker compose run app python manage.py procesar_pedidos --hasta-vaciar` mientras el `worker` trabaja) marca como interrumpido el pedido que el `worker` sigue ejecutando, y después `finish` lo vuelve a `done` sin comprobar su estado. En los tests usá `jobs.run_next()` o el comando con `--hasta-vaciar` sobre la base de pruebas, nunca contra el entorno con el `worker` arriba.

## De la verificación de T-067 (2026-10-03)

- La base no hace valer que `tenders_reading` y `tenders_segment` "no se modifican" (plan, "Modelo de datos"): un `UPDATE tenders_segment SET text = ...` se acepta. Solo `tenders_run_step`, `tenders_requirement_change` y el contenido de una versión validada tienen triggers. Las funciones de carga y lectura no deben modificar una lectura ni sus tramos después de crearlos; si hace falta leer de nuevo, se crea otra lectura con `sequence` siguiente (única por documento).
- `Segment.text` debe ser igual a `canonical_text[char_start:char_end]`. La base solo comprueba `char_end >= char_start`; la igualdad es responsabilidad del código que crea los tramos.

Para pruebas manuales, solo el caso-00. El caso-01 trae 2 circulares reales (REQ-031) y 52 páginas (tiempo de un pliego de unas 50).
