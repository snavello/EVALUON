## Desvíos juzgados contra el plan y la spec

| Desvío | Juicio |
|---|---|
| `unit` como FK PROTECT a `norms.Unit` (dependencia de `norms 0007`) | No contradice. El plan dice "id de `norms_unit`"; la FK lo cumple y agrega integridad. Efecto: la migración de `tenders` depende de `norms 0007` (ya en main) y una unidad con respaldo no se puede borrar de la normativa; coherente con P6. |
| `process=''` en filas viejas | No contradice. El plan dice "`level` queda como dato histórico"; `process` vacío es lo único honesto para propuestas hechas antes del proceso único. |
| `FILTER_MOTIVES` suma `consecuencia_sancion` y `derecho_posterior` | No contradice. El plan (línea de clasificación) los agrega a los del ADR-0019 con los nombres `consecuencia_o_sancion` y `derecho_posterior`; el código usa `consecuencia_sancion` para el primero. Aviso: T-102 y las instrucciones deben usar exactamente el identificador de `FILTER_MOTIVES`. |
| `MATRIX_SAMPLE_DISCARDED = {"every": 3, "minimum": 20}` | No contradice: es la forma estructurada de "uno de cada tres, mínimo 20". |
| `NORM_SUPPORT_MIN_SCORE = RERANK_THRESHOLD` | No contradice: es el valor inicial que fija el plan y la ficha. |
| Técnico con cita `repetida` no prohibido | No contradice: el plan dice "un técnico no cambia". Test que lo fija. |

Ninguno contradice el plan ni la spec.
